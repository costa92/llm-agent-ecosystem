## 1. 设计定位

**产品隐喻:制片厂(Studio)。** 用户给一句创意 brief,系统像一条制片流水线把它跑成剧本、分镜、图片素材;人是制片人,握采纳/退回的硬门禁。UI 的核心任务有两个,优先级排死:

1. **看清流水线正在发生什么**——todo 图是异步的、分钟级的、可能失败重试的,时间线必须实时、可回放、一眼能定位卡点。
2. **高效审图**——admin 的审核动作(采纳/退回/改 Prompt 重生成)是产品价值闭环,审核界面按"单手键盘流"设计。

**视觉基调:暖石墨深色工作台。** 选深色不是风格偏好而是功能选择:核心场景是审看生成图片,深色中性底让素材色彩不被环境干扰(同 Frame.io/达芬奇调色台的逻辑)。在深底之上,品牌强调色取**打板琥珀**(场记板黄),流水线四阶段各有一个功能性阶段色,用于时间线、状态徽标、看板列的一致编码——颜色即信息,不做装饰。

**签名元素:「制片轨道」。** 项目工作台中央的垂直流水线时间线:Planner 产出的 todo 图渲染为带依赖连线的节点轨道,SSE 事件实时给节点上色;`running` 节点显示黄黑斜纹呼吸条(场记板纹),`failed` 节点红色并展开错误与重试计数。这是整个产品被记住的一屏。

## 2. 技术栈建议(供 UI 实现阶段)

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript + Vite | SPA,与后端 embed 静态资源部署模型匹配 |
| 路由 | TanStack Router | 类型安全路由参数(org/project id 贯穿全站) |
| 服务端状态 | TanStack Query | REST 列表/详情缓存 + SSE 事件到来时 `invalidate` 精准刷新 |
| SSE | 原生 `EventSource` 封装 hook | `/events/stream` 断线自动重连,带 `Last-Event-ID`(=`run_events.seq`)续传;首屏先拉 `GET /events` 分页回放再接流 |
| 样式 | Tailwind CSS + CSS 变量 token | token 见 §4,变量化便于后续主题 |
| 全局状态 | Zustand(轻量) | 当前 org、用户角色、SSE 连接状态 |
| 图表 | Recharts(成本中心) | 仅成本页用,按需加载 |
| 表单 | react-hook-form + zod | brief 表单、模型配置表单校验 |

**鉴权接线:** JWT 存内存 + refresh token 走 `POST /api/auth/refresh` 静默续期;401 统一拦截跳登录。角色(viewer/editor/admin)由会话接口下发,前端只做**显隐**,不做安全边界(后端 RBAC 是真门禁)。

## 3. 信息架构与导航

```
登录 ─→ 组织选择(多 org 时) ─→ 应用框架
应用框架 = 左侧图标导航栏(64px) + 内容区
  ├── 项目        /orgs/:org/projects            (全角色)
  │     └── 项目工作台  /projects/:id             (全角色;运行/取消按钮 editor+)
  │           ├── Tab: 流水线(默认) · 剧本 · 分镜 · 素材
  │           └── 审核入口角标(admin)
  ├── 审核看板    /orgs/:org/review               (admin;聚合全项目待审资产)
  ├── 资产库      /orgs/:org/assets               (全角色)
  ├── 成本中心    /orgs/:org/cost                 (admin)
  ├── 模型配置    /orgs/:org/models               (admin)
  └── 底部: org 切换 · 成员管理(admin) · 用户菜单/登出
```

导航规则:viewer 看不到审核/成本/模型入口(直接不渲染);editor 额外看到"新建项目/运行";admin 全量。跨 org 一律经 org 切换器,URL 内 org 段是单一事实来源。

## 4. 设计系统(Design Tokens)

### 4.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--bg-base` | `#17191E` | 页面底色(暖石墨) |
| `--bg-surface` | `#1F232A` | 卡片/面板 |
| `--bg-raised` | `#272C34` | 浮层、悬停、输入框 |
| `--line` | `#343A44` | 描边/分隔线(1px,不用阴影分层) |
| `--text-1` | `#EDEEF0` | 主文本 |
| `--text-2` | `#9AA1AC` | 次级文本 |
| `--text-3` | `#666D78` | 占位/禁用 |
| `--amber` | `#E8A33D` | 品牌强调:主按钮、当前导航、running 斜纹 |
| `--stage-script` | `#5C9BD6` | 阶段·剧本(S2) |
| `--stage-board` | `#9C7BDA` | 阶段·分镜(S3) |
| `--stage-asset` | `#E8A33D` | 阶段·素材(S4,与品牌色合一) |
| `--stage-review` | `#4FB286` | 阶段·审核(S5)/ accepted / done |
| `--danger` | `#E05F5B` | failed / rejected / 删除 |
| `--info-dim` | 各阶段色 12% 透明 | 徽标底、时间线节点底 |

**todo 状态映射(全站一致):** `pending`=灰描边空心 · `ready`=灰实心 · `running`=琥珀+黄黑斜纹呼吸 · `done`=阶段色实心 · `failed`=红+重试计数 · `blocked`=灰虚线 · `canceled`=灰删除线。资产状态:`pending_acceptance`=琥珀徽标 · `accepted`=绿 · `rejected`=红。

### 4.2 字体

| 角色 | 字体 | 用法 |
|---|---|---|
| 中文界面 | `"Noto Sans SC", system-ui` | 全部 UI 文案;标题 600,正文 400 |
| Latin 显示/大数字 | `"Space Grotesk"` | 页面大标题、成本大数字、空状态 |
| 数据等宽 | `"JetBrains Mono"` | todo id、时间戳、token 用量、金额、prompt 文本 |

类型刻度:12 / 13(正文)/ 15 / 18 / 24 / 32。行高 1.5,等宽场景 1.4。

### 4.3 间距与形态

8px 网格;卡片圆角 10px、按钮/输入 8px、徽标 999px。分层靠 1px `--line` 描边 + 表面色阶,不用投影(深色 UI 投影脏)。焦点环:2px 琥珀外描边(键盘可达性硬要求)。动效:仅三处——时间线节点状态变更(150ms 色彩过渡)、running 斜纹滚动、审核通过后的卡片淡出;`prefers-reduced-motion` 时全部退化为瞬时切换。

### 4.4 核心组件清单

`StageBadge`(阶段徽标) · `TodoNode`(轨道节点) · `PipelineRail`(制片轨道) · `AssetCard`(素材卡,含状态角标/版本号) · `ReviewDrawer`(审核抽屉) · `PromptEditor`(等宽编辑器+风格选择) · `VersionTree`(版本血缘) · `CostStat`(大数字统计) · `SSEStatusDot`(连接状态点:实时绿/重连黄/离线灰) · `EmptyState` · `ConfirmDialog`(危险操作) · `CursorPager`(keyset 分页"加载更多")

## 5. 视图详设

### 5.1 登录

居中单卡(360px):产品标识(场记板式 logo 字标)+ 邮箱/密码 + 登录按钮。错误内联展示(不弹 toast)。登录成功:单 org 直进项目列表;多 org 进组织选择。对接 `POST /api/auth/login`,refresh 静默。无注册入口(成员由 admin 邀请,文案注明"请联系组织管理员")。

### 5.2 项目列表 / 新建项目

```
┌──────────────────────────────────────────────────────────┐
│ 项目                                    [筛选状态▾] [+ 新建项目] │
├──────────────────────────────────────────────────────────┤
│ ┌────────────┐ ┌────────────┐ ┌────────────┐             │
│ │ 国风茶饮短片 │ │ 赛博城市MV  │ │ 绘本《小狐》│   …卡片网格   │
│ │ ●running    │ │ ●review 3待审│ │ ●completed │             │
│ │ S2━S3━S4░░  │ │ S2━S3━S4━S5 │ │ 全部完成    │             │
│ │ 短视频·抖音  │ │ MV·B站      │ │ 绘本·印刷   │             │
│ └────────────┘ └────────────┘ └────────────┘             │
└──────────────────────────────────────────────────────────┘
```

- 卡片要素:项目名、状态徽标(七态各有色)、**迷你阶段进度条**(四段,按 todo 完成度上色,与制片轨道同色系)、content_type·target_platform·style 元信息、待审数角标(admin 可见,点击直达审核)。
- 新建项目 = 右侧滑出抽屉(不离开列表):名称、创意 brief(多行,带"一句话描述你要的内容"占位文案)、内容类型(短视频/绘本/MV…)、目标平台、风格(七风格选择器,带小样卡:日漫/吉卜力/皮克斯/迪士尼/写实/赛博朋克/国风)。提交后直接进入工作台并高亮"运行"按钮。
- 空状态:大字 "把一句创意,交给流水线" + 新建按钮(editor+;viewer 显示"暂无项目")。
- 对接:`GET/POST /api/orgs/{org}/projects`,cursor 分页。

### 5.3 项目工作台(核心屏)

三栏布局,中央是签名元素「制片轨道」:

```
┌ 项目头:名称 · 状态徽标 · brief 摘要 ─── [运行/重跑] [取消] ┐
│   running 时:头部下沿 3px 黄黑斜纹滚动条(场记板纹)        │
├──────────┬──────────────────────────┬──────────────────┤
│ 左:计划   │ 中:制片轨道(SSE 实时)      │ 右:工件预览        │
│ brief 全文│  ◉ S1 Planner   done      │ 选中节点的产物:    │
│ 风格/平台 │  │                        │ · script→剧本摘要  │
│ 计划信息: │  ◉ S2 剧本      done      │ · storyboard→镜头表│
│ plan 状态 │  │                        │ · asset→图片缩略   │
│ 是否回落⚠ │  ◉ S3 分镜      done      │   +prompt+provider │
│ (fallback │  ├─┬─┬─┐ (按依赖分叉)      │ · failed→error 全文│
│  _used 时 │  ▨ ▨ ◉ ○  S4 素材×8      │   +attempts+重试时间│
│  黄条提示)│  │ running done pending   │ [在剧本/分镜 Tab    │
│ 事件日志  │  ◌ S5 审核  blocked       │  中打开]           │
│ (折叠流)  │  连线=depends_on          │                  │
└──────────┴──────────────────────────┴──────────────────┘
Tab 切换:流水线(上图) · 剧本 · 分镜 · 素材
```

- **制片轨道交互:** 节点=todo,按 `depends_on` 画连线;并行 todo(如每 shot 一个 asset)横向分叉成节点组,组内显示 `done/total` 计数。点击节点 → 右栏加载该 todo 工件;hover 显示 `todo_id`(等宽)、attempts、耗时。`failed` 节点展开错误信息;`blocked` 虚线表明在等前驱。
- **SSE:** 进入页面先 `GET /events` 回放历史给轨道定色,再接 `/events/stream`;右上 `SSEStatusDot` 显示连接态,断线自动重连并以最后 seq 续传,重连期间轨道置"可能滞后"浅黄提示。事件 toast 只发两类:`asset_generated`(带"去审核",admin)和 `run_done`。其余只更新轨道,避免轰炸。
- **运行/重跑(editor+):** 重跑=重规划,弹确认("将重新规划并生成新 todo 图,历史工件保留")。取消同理确认。viewer 不渲染这两个按钮。
- 项目状态机文案:draft=待运行 / planning=规划中 / running=生产中 / review=待审核 / completed=已完成 / failed=失败 / canceled=已取消。

### 5.4 剧本视图(Tab)

阅读优先的单栏文档版式(max-width 720px):故事梗概、人物卡(横滑)、场景/对白分节。右上角:版本号(等宽)+ todo 来源链接。JSON 容错解析失败的字段显示"原始输出"折叠块(等宽),不让前端崩——对应后端 R1 风险。

### 5.5 分镜栅格(Tab)

```
┌ shot 卡 ──────────────┐
│ #03  ▢缩略(有asset时)  │   网格 3–4 列,按 ordering 排序
│ 镜头: 中景·推          │   每卡:shot_no(等宽大字)、camera、
│ 场景: 茶馆内,黄昏       │   scene、action、duration
│ 动作: 主角抬头…         │   底部:prompt 预览(等宽,2行截断,
│ prompt: a cinematic…   │   点击展开)+ 该 shot 资产状态点
└───────────────────────┘
```

点击卡片 → 侧滑详情:完整 prompt、关联资产(各版本缩略)、"用此 shot 重生成"(admin,预填 prompt 进审核流的重生成弹窗)。

### 5.6 审核看板(admin 核心屏)

org 级聚合(也可从项目角标带 project 过滤进入)。**不是拖拽看板**——采纳/退回是按钮动作,布局为"待审网格 + 审核抽屉":

```
┌ 筛选:项目▾ 风格▾ 类型▾   待审 12 ───────────────────────┐
│ ┌图┐ ┌图┐ ┌图┐ ┌图┐    点击任意卡 → 右侧审核抽屉(60%宽) │
│ └──┘ └──┘ └──┘ └──┘   ┌─────────────────────────┐      │
│ ┌图┐ ┌图┐ …            │ 大图(可缩放/原图签名URL)   │      │
│                        │ prompt(等宽,可见全文)      │      │
│                        │ 风格·provider·model·shot   │      │
│                        │ 版本血缘:v1→v2(当前)       │      │
│                        │ [✓采纳 A] [✗退回 R]        │      │
│                        │ [✎ 改 Prompt 重生成 E]     │      │
│                        └─────────────────────────┘      │
└─────────────────────────────────────────────────────────┘
```

- **键盘流:** `A` 采纳 / `R` 退回 / `E` 重生成 / `←→` 切上下张;操作完成后自动跳下一张待审——审核是高频批量动作,效率即体验。
- **重生成:** 抽屉内展开 `PromptEditor`:编辑后 prompt(等宽)、风格切换、参数(size/quality);提交 → `POST /assets/{id}/regenerate`,toast"已派生重生成任务",新版本生成后回到待审且血缘 `v(n+1)`,旧版可在血缘里对照。
- **409 处理:** 他人已处理该资产 → 内联提示"已被处理(accepted/rejected)",卡片自动移出待审,不弹错误。
- 图片一律走响应中的短 TTL `signedUrl`;过期(403)自动重取详情刷新 URL。
- 二期扩展位:type 筛选预留 video/audio;抽屉媒体区按 type 切换 `<img>/<video>/<audio>` 渲染器。

### 5.7 资产库

```
┌ 左过滤栏 180px ─┬─ 素材瀑布流网格 ──────────────────────┐
│ 类型 ▢图片      │ ┌图 v2 ●accepted┐ ┌图┐ ┌图┐ ┌图┐     │
│ 状态 ▢accepted… │ 卡:缩略·状态角标·版本号·风格标签        │
│ 风格 ▢国风…     │                                       │
│ 标签 [输入]     │            [加载更多](cursor)          │
│ 项目 ▾         │                                       │
└────────────────┴───────────────────────────────────────┘
```

点击 → 资产详情页:大图 + 元数据 + **版本血缘树**(`parent_asset_id` 链,纵向节点,当前版本高亮,可任选版本查看大图与 prompt diff)+ 所属项目/shot 反链。viewer 只读;admin 在详情页也能直接审核待审版本。对接 `GET /api/orgs/{org}/assets`(标签/风格/项目/类型过滤 + keyset 分页)。

### 5.8 成本中心(admin)

顶部三个 `CostStat` 大数字(本月成本 / 生成次数 / token 用量,Space Grotesk + 等宽小数),下方:按项目聚合条形图(Recharts,阶段色复用)+ 按 provider/model 明细表(等宽数字右对齐:时间、project、provider、model、用量、金额)。时间范围切换(7天/30天/自定义)。表格行点击 → 反链到对应项目。对接 `GET /api/orgs/{org}/cost`、`GET /api/projects/{id}/cost`。配额接近上限时页头黄条预警(对应 R6 成本失控)。

### 5.9 模型配置(admin)

左:model-catalog(生态可用 provider/model 目录,只读);右:org 已配置 model_configs 列表(provider、model、用途 chat/image、状态)。新增 = 抽屉表单:从 catalog 选 provider+model、填别名、API key **只写不回显**(保存后显示 `sk-····后4位`),与"凭据永不下发浏览器"原则一致。删除二次确认。

### 5.10 成员管理(admin,从底部导航进)

成员表(邮箱、角色、加入时间)+ 邀请(邮箱+角色)+ 改角色/移除。角色说明内联:viewer 只读 / editor 可建项目与运行 / admin 可审核与管理。

## 6. 横切规范

- **加载:** 列表骨架屏(卡片轮廓);轨道首次加载显示灰色占位节点。所有变更按钮 pending 态禁用+spinner。
- **错误:** 表单错误内联;请求错误 toast(含可重试按钮);SSE 断线不弹 toast 只变状态点。403(跨 org/越权)统一"无权访问"页。
- **空状态:** 每屏都有定向文案+动作(§frontend 写作原则:空屏是行动邀请),如审核看板空="暂无待审素材,流水线产出后会出现在这里"。
- **危险操作:** 删项目、取消运行、退回资产、删模型配置 → `ConfirmDialog`,主按钮红。
- **响应式:** 桌面优先(生产工具);≥1280 三栏,1024–1280 工作台右栏折叠为抽屉,<768 只保证项目列表/审核抽屉可用(移动端定位为"看进度+应急审核")。
- **可达性:** 全部交互可 Tab 达 + 琥珀焦点环;状态不只靠颜色(徽标都带文字);审核快捷键在抽屉内显示提示。
- **i18n:** 一期固定中文,文案集中 `locales/zh-CN.ts` 便于后续扩展。
