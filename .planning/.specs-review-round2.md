# 二轮评审收敛结论（kb + studio specs）

日期：2026-06-09。评审者：Plan-agent×2（新焦点） + codex（read-only 跨 AI）。三方独立、结论收敛。
裁定：**均判定不可进入实现计划，有 HIGH 阻塞。** 修订后需第三轮复审确认收敛。

## 跨 spec（最高优先，结构性）

- **X1 [HIGH] kb 与 studio 的 org/user/membership/RBAC/JWT 实质分歧，却都自称"复用同一模式"。** 分歧：角色枚举 kb `{admin,writer,reader}` vs studio `{admin,editor,viewer}`；kb 有 org 级 nullable 二级作用域，studio 只有 workspace 级（连"列举本 org 下 workspace"都没建模）；表名 `app_user`/`org` vs `users`/`orgs`。两者都缺 refresh-token/session 表、轮换、登出、吊销、cookie refresh 的 CSRF 立场。
  - 修：抽共享包/仓 `llm-agent-authz`（或 `-tenant`）：argon2id + JWT 签发/校验 + Authenticator(预留OIDC) + `sessions(refresh_hash,expires_at,revoked_at)` + membership 解析中间件，二级资源作用域（kb vs workspace）参数化，角色枚举统一三元组。**kb 是 first mover，须在 kb 动工前定。**

## kb HIGH

- **K1 [HIGH] `RagPort` 含 AskGlobal/AskDrift 不成立**：`*otelrag.Wrapper` 只暴露 `Import/Retrieve/Ask`（otelrag.go:99/124/145），**无** `AskGlobal/AskDrift/PrewarmCommunityReports`，且 `inner` 非导出未内嵌。一轮的"两类型都实现 RagPort"修法是错的。
  - 修：`ragsvc` 写 thin 适配器实现完整 `RagPort`——`Ask/Import` 委托 Wrapper（带 span），`AskGlobal/AskDrift/Prewarm` 委托 `Wrapper.Inner()` 并自建 span。
- **K2 [HIGH] 重导去重锚点错 + 删除/级联完全缺失**：`ReplaceSource` 按 `Document.SourceID` 删旧 chunk（import.go:73, splitter.go:77-91），但 spec 从不设 `SourceID`→重导=堆叠重复。`Metadata{doc_id}` 冗余（citation.DocID 来自 `Chunk.DocID=doc.ID`）。`*rag.System` 无导出删除（仅 `Remove(chunkID)`），按 doc/namespace 删要直接用 `postgres.Store.RemoveByFilter`+`RemoveGraphBySource`+community 清理。
  - 修：`Document.ID=业务 document.id`、`Document.SourceID=稳定源标识`、`Checksum` 仅做"内容未变跳过"短路；删掉 Metadata{doc_id}；新增 `DELETE /api/kb/{id}/documents/{docId}` 与 `DELETE /api/kb/{id}`，定义级联顺序(chunks→graph→community→业务行)+事务；`ragsvc` 直接持有 `postgres.Store` 引用做删除。
- **K3 [HIGH] URL 摄入 SSRF + 上传校验缺失**：`net/http` 抓任意 URL→可打云元数据/内网。multipart 无 MIME/大小/配额校验→解析炸弹/OOM。
  - 修：URL：限 http/https + DNS 解析后校私网/环回/链路本地 IP（防 rebinding，用解析到的 IP 连）+ 禁内网重定向 + 超时 + 大小上限 + MIME 白名单。上传：`MaxBytesReader` + content-type 白名单 + 每 kb 存储配额。§11 新增"出站 SSRF 防护"。
- **K4 [HIGH] auth/org/kb/membership CRUD 端点几乎全缺**：全 spec 仅 4 个 POST（documents/ask[/global|/drift]/eval/run），但 §10 前端需登录/org/kb 列表创建/成员管理/文档列表删除/会话列表/文档详情轮询。
  - 修：补端点目录含请求/响应 JSON：`POST /api/auth/{login,refresh,logout}`、`GET/POST /api/orgs`、`GET/POST /api/orgs/{org}/kbs`、`GET/DELETE /api/kb/{id}`、`GET/POST/DELETE /api/kb/{id}/memberships`、`GET /api/kb/{id}/documents`(分页)、`GET/DELETE …/documents/{docId}`、`GET …/sessions`。

## kb MED（修订时一并吸收）

- K5 [MED] §8 "SecurityFilters+Namespace 双层"对 GraphRAG 夸大：`SecurityFilters` 只在 search/ask（options.go:19-24），`GlobalOptions`/`DriftOptions` 只有 Namespace+图参数。→ 明确 global/drift 隔离仅靠 namespace（RBAC 之后），文档级 ACL 不经 global/drift。
- K6 [MED] eval 返回类型名精确化：`GlobalEvalResult`/`DriftEvalResult`（非 GlobalResult）；`WriteBenchmarkJSONL(w io.Writer, r BenchmarkResult)` 需调用方自备 Writer。
- K7 [MED] 分页全缺（文档/会话/eval_run/列表）→ 统一 cursor 分页。
- K8 [MED] `ingest_job` 太薄：缺 `next_run_at/locked_by/locked_until/dead 终态/idempotency key/阶段进度`；缺 stuck-job 回收 + 手动重试端点。
- K9 [MED] PII/注入 guard 接入点未落实；org 级 vs 库级角色合并规则未定义（越权核心歧义）→ 给角色解析算法 + 越权矩阵测试。

## studio HIGH

- **S1 [HIGH] v2 checkpoint 需对每个跨 suspend 的非 string port 类型 `RegisterCodec`**：codec.go:50 对未注册类型返回 `ErrNotCheckpointable`，init 只内置 string（codec.go:80）；carrier=any。RAG `hits`/工具结构化 map 在含 approval 的 v2 flow suspend 时直接崩。flowd 蓝本只注册 passthrough/approval（全 string）故没踩到。
  - 修：新增"v2 port codec 注册"节——双注册时对每个 v2 节点非 string 输出 `flow.RegisterCodec[T](name)`，或强制 carrier 收敛为 `json.RawMessage`/string 并注册之。E2E 加"RAG+approval flow suspend/resume"。
- **S2 [HIGH] resume 按 flowID 重建引擎、不按 pinned version**：flowd `engineForV2(rec.FlowID)`（server.go:811）无 version 维度；新 IR 缺中断节点→`interrupt node not found`（resume.go:144）。与 studio 版本化冲突。
  - 修：engine LRU cache key=`(flow_id, version, engine_kind)`；resume 读 `flow_runs.version`→取 `flow_versions.ir_json`→编译 v2 engine→Resume；`POST run` 必须 pin version。
- **S3 [HIGH] MCP stdio 节点=任意命令 RCE 且 editor 可触发**：`transport_stdio.go:38/39` `exec.Command(command,args...)` 直接执行用户传入命令；§8 MCP schema 列 `command+args` 用户可配；§10 editor 可建/触发 flow。editor 可 `{transport:stdio,command:/bin/sh,args:[-c,...]}` 在宿主机 RCE。terminal 节点已有禁用/白名单门禁，MCP stdio 却零门禁。
  - 修：MCP stdio 默认禁用，启用需 admin + 服务端命令白名单（用户不能自由填 command），或 v1 只支持 MCP http transport + admin 预置 server 引用。对齐 terminal 门禁范式。
- **S4 [HIGH] HITL 实时事件契约自相矛盾**：§9 说 v2 不走 `/run/stream`，又说前端"收到 `flow_suspended`"。flowd 拒绝 resumable streaming（server.go:436），v2 事件只在 RunResumable/Resume 返回后合成。
  - 修：定义 v2 专用实时事件端点（如 `GET /runs/{runID}/events/stream`），或明确 HITL 时间线由"非流式 run/resume 响应 + 事件历史轮询"填充。
- **S5 [HIGH] M1/M3 engine_kind 与 approval 节点隐藏耦合**：M1 是纯 v1、无 v2/分诊（M3），但 approval 是 v2-only；若 M1 画布能拖 approval→保存分诊成 v1→`unknown type`。
  - 修：M1 画布按 `/node-types` 的 `v2Only` 过滤（M1 不暴露 approval）；`engine_kind` 列 M1 即建但恒 v1，分诊函数 M3 接管。

## studio MED

- S6 [MED] 并发编辑/运行语义缺：`flow_versions` 无 `base_version`/ETag；run 未说跑 latest 还是 pinned。→ save 要 `If-Match`/`base_version`+409；run pin version；resume 用 checkpointed version。
- S7 [MED] v1 string carrier vs v2 any carrier vs spec 声明 JSONB 不一致（store.go:50-54 是 map[string]string；v2 flowd stringify outputs server.go:877-890）。→ 明确 studio 自有 JSON API 形状 + 每节点 stringify 位置。
- S8 [MED] suspended run 永不 resume 的 TTL/清理缺（checkpoint 泄漏）；MCP stdio 子进程生命周期/僵尸回收（必 `defer transport.Close()`）；node-types schema 与注册漂移（响应加 `v2Only`，保存校验）；取消/超时 run 终态（补 `canceled`）。
- S9 [LOW] resume token 服务端取自 `flow_runs.resume_token`、client 不传（server.go:816）；checkpoint token==runID 一 run 一活 checkpoint，多级审批靠同 token 反复 Save/Resume；`InterruptRequest.Kind` 是 string 非 Go enum，studio 自校验值域；`FromAgentTool` 跨 import 路径靠 contract alias 兼容（adapter_llmagent.go:7-15）——spec 点明避免困惑。

## 已确认正确（无需改）
cel.NewEvaluator()、confirm_dangerous、NewInMemoryTransport(handler)、resumable 拒绝 stream 端点、v2 `Deps struct{}` 靠闭包注入、GraphRAG 组件符号名、SecurityFilters 不可绕过（仅 search/ask 路径）、rag ≥v1.9.0 配额。
